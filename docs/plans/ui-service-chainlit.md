# Plan: ui_service → Chainlit chat UI (MCP + ingestion)

> **Status: implemented** (phases 1–5; phase 6 docs updated in README).
> Deviations from the plan:
> - Citation elements are named `[n]`, not `S{n}`, so the model's own markers link without rewriting.
> - The answer endpoint is `/tasks/generate` with an `answer_style` field. llm_service also has `/tasks/select-tools`.
> - Header links have no Admin entry; admins reach `/admin` from the Documents page.
> - The `/` route redirects to `/chat/` (trailing slash, Chainlit mount).

## Context

`ui_service` serves hand-written HTML pages: login, admin, OCR single and
batch, history, and a basic `chat.html`. The chat page works, but it is a
custom page with no chat history, no MCP support and no upload from chat.

The goal is a modern RAG chat UI built on **Chainlit 2.12.0**:
- shows the 10-step pipeline live
- answers with clickable citations
- **ingests documents straight from the chat** (Docling OCR → chunk → index)
- supports **MCP**: users can connect their own MCP servers and their tools feed answers
- keeps auth_service, access control (private/shared) and the orchestrator pipeline unchanged

Chainlit was chosen over Open WebUI and LibreChat because those bring their
own RAG, user database and storage, which would replace this project's
pipeline instead of presenting it.

## Target architecture

```
Browser ──▶ ui_service (FastAPI, :8000)
              ├─ /login, /change-password, /admin, /history, /ocr, /batch   existing pages (kept)
              ├─ /documents/*, /preview/*, /ocr*, /rag/*                    existing proxies (kept)
              └─ /chat  ── Chainlit app (mount_chainlit) ──────────────────  NEW main UI
                    │  auth   : header_auth_callback ← existing session cookie (single sign-on)
                    │  chat   : orchestrator /chat (SSE) → cl.Step per pipeline step
                    │  upload : ocr_service /ocr → rag_service /ingest/{id} status
                    │  MCP    : user-connected MCP servers → tool results as extra evidence
                    └  history: MinIO data layer (chat/{user_id}/{thread_id}.json)
```

`/` redirects to `/chat`. The old single-OCR page moves from `/` to `/ocr`.
`templates/chat.html` and its CSS are removed.

## Phase 1: Chainlit shell, single sign-on, pipeline streaming

1. **Mounting.**
   - In [main.py](../../ui_service/src/main.py), call `mount_chainlit(app, target="src/chat_app.py", path="/chat")` after all FastAPI routes are defined, so the existing routes take precedence.
   - `GET /` redirects to `/chat`; the single-OCR page moves to `GET /ocr`.
   - Add `CHAINLIT_AUTH_SECRET` (random, in `.env`). Chainlit uses it to sign its own JWT.
2. **Single sign-on.**
   - `@cl.header_auth_callback` reads the `montashi_session` cookie from the request headers and validates it with the existing `auth_client.validate()`.
   - It returns `cl.User(identifier=username, metadata={"id", "role"})`.
   - `AuthMiddleware` already redirects unauthenticated `/chat` requests to `/login?next=/chat`, so the existing login page stays the only sign-in.
   - `@cl.on_logout` also calls auth_service logout and clears the cookie.
3. **Starters** (`@cl.set_starters`): fact, comparison, catalog ("How many documents did I upload?"), web ("Latest news about …"), and a Drive starter for admin/master only.
4. **Pipeline streaming** (`chat/pipeline_stream.py`).
   - `on_message` POSTs `{question, history}` to orchestrator `/chat` with identity headers from `cl.user_session["user"].metadata`.
   - History is the last 6 turns, kept in `cl.user_session`.
   - One parent `cl.Step("RAG pipeline")`, with a child step per event:

     | Step | Shows |
     |---|---|
     | `3 · Understanding` | intent + standalone question |
     | `4 · Transformation` | rewrites, sub-questions, HyDE |
     | `5 · Routing` | routes + reason |
     | `6 · Retrieval` | per-route counts and status (`unavailable` highlighted) |
     | `7 · Reranking` | top sources and scores |
     | `8 · Compression` | blocks, tokens, dropped, merged |
     | `9 · Generation` | – |
     | `10 · Validation` | action + groundedness; a retry opens a second attempt group |

   - The final `cl.Message` carries the answer plus a footer line: badge (grounded / low confidence / needs clarification / not enough evidence), routes, groundedness %, PII redactions, elapsed time.
   - `error` events become an error message naming the failing service.
   - Set `cot = "full"` in config.toml so the steps are visible. A user setting can hide them (phase 3).
5. **Citations** (`chat/citations.py`).
   - The answer's `[n]` markers are rewritten to `[S{n}]`.
   - One `cl.Text(name=f"S{n}", display="side")` element per citation: source name, page or URL, the evidence snippet, and a link (`/documents/{id}/source`, Drive `webViewLink`, or the web URL). Chainlit links element names in the message text, so `[S1]` opens the side panel.
   - **Backend change:** add `snippet` (first ~500 chars of the evidence text) to `Citation` in `llm_service/src/schemas.py` and fill it in `generation/answer.py::_citations`. The orchestrator passes it through untouched.
6. **Branding.** `[UI] name = "Advanced Hybrid RAG"`, logos, `theme.json` in the current palette, and header links ("Documents" → `/history`, "Batch upload" → `/batch`, "Admin" → `/admin`, admins only via CSS/JS check).
7. **Cleanup.** Delete `templates/chat.html` and the chat CSS block in `style.css`. Nav "Chat" links point to `/chat`; the `/rag/chat` and `/rag/query` proxies stay for API use.

## Phase 2: Ingestion from the chat

1. config.toml `[features.spontaneous_file_upload]`: `enabled = true`, `accept = ["application/pdf", ".docx", "image/png", "image/jpeg"]`, `max_files = 5`, `max_size_mb = 50`.
2. `chat/ingestion.py`, called from `on_message` when `message.elements` contains files:
   - one `cl.Step("Ingest {name}")` per file, steps running concurrently up to 2 at a time
   - **OCR**: POST multipart to ocr_service `/ocr` with identity headers, showing "Docling OCR…" with page count and seconds when done
   - **Indexing**: poll rag_service `GET /ingest/{doc_id}` every 2 s (timeout 10 min) until `status == ok|error`, showing "Indexed N chunks (M tables) · doc_type · topic"
   - on success, show `cl.Action`s: **Share with everyone** (PATCH ocr `/documents/{id}/access`), **Open document** (`/documents/{id}/source`), **Summarize** (sends "Summarize {name}" through the pipeline)
   - if the message also has text, the question is answered after ingestion finishes, so it can use the new document
3. `RAG_SERVICE_URL=http://rag_service:8003` is added to ui_service env.
   - Ownership is checked through ocr_service `GET /documents/{id}` (identity-scoped) before reading rag status. `/ingest/*` itself has no identity check.
4. Sharing: `@cl.action_callback("share_document")` and `("unshare_document")` call the existing ocr access proxy and update the action label.

## Phase 3: Chat settings and slash commands (route control)

1. `cl.ChatSettings` (sent on chat start):
   - Switch "Search the web" (default on)
   - Switch "Search Google Drive", shown only for roles in `GDRIVE_ALLOWED_ROLES`
   - Switch "Show pipeline steps"
   - Select "Answer style" (auto / concise / detailed)
   - Stored in `cl.user_session["settings"]`.
2. Commands (`cl.context.emitter.set_commands`):
   - `/docs`: only my documents
   - `/web`: force web search
   - `/drive`: force Google Drive (if permitted)
   - `/catalog`: questions about the collection
   - `/ingest`: hint to attach files
3. **Backend changes:**
   - **orchestrator `/chat`** accepts optional fields and forwards them:
     - `route_hint: list[str]` replaces the routing decision when set
     - `deny_routes: list[str]` comes from the disabled switches
     - `answer_style`
   - **rag_service `/route`** honours `route_hint` and `deny_routes`, still filtered by `available_routes(identity)` so the UI can't escalate Drive access.
   - **llm_service** takes `answer_style` into the answer prompt as an extra format line.

## Phase 4: MCP

Two kinds of MCP servers:

| Kind | Where it runs | How it is used |
|---|---|---|
| **Built-in** (Google Drive, web search) | rag_service `/mcp/*` (existing) | chosen by the router, as today. Not exposed to the browser: `MCP_TOKEN` stays server-side |
| **User-connected** | any streamable-HTTP / SSE MCP server the user adds in Chainlit's MCP panel | tools are selected per question and their results join the evidence pool |

1. config.toml:
   - `[features.mcp] enabled = true`
   - `[features.mcp.user_servers] enabled = true`, `allowed_urls` set from env `MCP_USER_ALLOWED_URLS`, rendered into config.toml at container start; an empty list means deny all.
   - stdio servers stay disabled for users.
2. `@cl.on_mcp_connect(connection, session)`:
   - `await session.list_tools()`; store `{name: {session, tools}}` in `cl.user_session["mcp"]`
   - show a system message listing the tools
   - `@cl.on_mcp_disconnect` removes the entry.
3. Using the tools for a question (`chat/mcp_tools.py`), only when the user has connected servers and the route isn't `direct`:
   1. **New llm_service task** `POST /tasks/select-tools {question, tools: [{server, name, description, input_schema}]}` returns `{calls: [{server, name, arguments}], reason}`. It is grammar-constrained, with at most 3 calls, and may return an empty list.
   2. ui_service runs each call through the user's `ClientSession.call_tool` with a 20 s timeout. Each result is shown as `cl.Step(type="tool")` with arguments and the truncated output.
   3. Text results become `external_evidence` items (`route="mcp"`, `source="{server}/{tool}"`, `owned=True`) and are sent to orchestrator `/chat`.
4. **Backend changes:**
   - **rag_service:**
     - `Route` gains `"mcp"`
     - `/retrieve` accepts `external_evidence: list[Evidence]`; they are chunked (`chunking_techniques/text.py`) and reranked in the same pool as docs, Drive and web
     - `route_status["mcp"]` is reported
   - **llm_service:** `Evidence.route` and `Citation.route` gain `"mcp"`; `format_evidence` shows the tool name as the source.
   - **orchestrator:** passes `external_evidence` through on every attempt, retries included.
5. **Safety.**
   - Tool output is untrusted text. It is only ever evidence and never instructions; the answer prompt already says "use only facts", and the judge validates it.
   - Tool arguments are shown to the user in the step.
   - The URL allowlist and Chainlit's built-in header restrictions prevent connecting to internal services.

## Phase 5: Chat history (MinIO data layer)

1. `chat/data_layer.py`: `MinioDataLayer(BaseDataLayer)` implementing
   - `get_user` / `create_user`, mapped onto auth identities with nothing stored
   - `create/update/delete_step`, `create/get/delete_element`
   - `list_threads` (paginated, filtered to the user), `get_thread`, `update_thread`, `delete_thread`, `get_thread_author`
   - `upsert/delete_feedback`, `get_favorite_steps`, `build_debug_url` (empty), `close`

   Storage layout:
   - threads: `chat/{user_id}/{thread_id}.json`
   - element files: `chat/{user_id}/{thread_id}/elements/{id}`

   An in-memory index per user is loaded lazily, the same pattern as the ocr_service and rag_service registries.
2. Registered with `@cl.data_layer`. The sidebar thread list, rename, delete and search work.
3. `@cl.on_chat_resume(thread)` rebuilds `cl.user_session["history"]` from the thread's user and assistant messages (last 6 turns).
4. Thumbs up/down feedback is stored on the step and also appended to `chat/feedback.jsonl`, which can later seed an evaluation set.
5. When an account is deleted, the existing ocr owner-wipe call is extended: ui_service deletes `chat/{user_id}/`.

## Phase 6: Legacy pages, docs

- Keep `/login`, `/change-password`, `/admin`, `/history` (Shared toggle), `/ocr`, `/batch` and update their nav: Chat · Documents · Batch · Admin.
- README: new screenshots, an "Using the chat" section (uploads, commands, MCP connections, settings) and the MCP allowlist config.

## Verification

1. **Login.** Log in at `/login` and get redirected to `/chat` without a second login. An expired session sends `/chat` back to `/login?next=/chat`. Logging out from Chainlit invalidates the auth_service session.
2. **Pipeline.** Ask "What is the late payment interest?":
   - the steps 3→10 appear live
   - the answer has `[S1]` chips that open the side panel with the snippet and a working "open document" link
   - the badge shows groundedness
3. **Retry.** An unanswerable question shows two attempt groups and an honest "not enough evidence" answer.
4. **Ingestion.** Drop a PDF into the chat:
   - OCR and indexing progress steps appear, then "Indexed N chunks"
   - a follow-up question in the same message is answered from it
   - **Share** makes it retrievable for a second user
5. **Settings / commands.**
   - With "Search the web" off, no web route runs, even for "latest …" questions.
   - `/web …` forces web.
   - A `user` role sees no Drive switch, and `/drive` falls back to docs.
6. **MCP.**
   - Connecting an allowlisted streamable-HTTP MCP server (e.g. a local FastMCP test server) lists its tools.
   - A question that needs a tool shows a tool step with arguments, and the tool output is cited as `server/tool`.
   - Non-allowlisted URLs are rejected.
   - Disconnecting stops tool calls.
7. **History.**
   - Threads appear in the sidebar after a reload.
   - Resuming a thread keeps the conversation context (follow-up "and the Pro plan?" works).
   - Users never see other users' threads.
   - Deleting the account removes `chat/{user_id}/`.
8. **Regression.** `/history`, `/ocr`, `/batch` and `/admin` still work, and the `/rag/query` API still answers.

## Risks / checks during implementation

- **Mounting Chainlit under `/chat`** next to `BaseHTTPMiddleware`:
  - check that socket.io (`/chat/ws/socket.io`) and static assets load through the middleware
  - Chainlit authenticates the socket with its own JWT; `AuthMiddleware` only sees HTTP
- **Element-name linking** (`[S1]` → side element): check the exact matching rules in 2.12. The fallback is plain links in a "Sources" list.
- **`header_auth_callback` headers:** check that the session cookie arrives in the headers Chainlit passes to the callback. The fallback is `password_auth_callback` calling auth_service `/auth/login` (one extra login form).
- The data-layer method signatures follow `chainlit/data/base.py` in 2.12.0. Pin `chainlit==2.12.0` and re-check on upgrades.
